# 项目架构

炮战演习。客户端用 Phaser 4 画一局回合制炮战，服务端用 Skynet 做权威结算。公式、房间规则和 12 种坦克见 [参考资料.md](参考资料.md)。

## 目录

```
fortress/
  Client/          Phaser 4 + Vite + TypeScript。默认 http://localhost:5180
  Server/          四个 Skynet 进程。网关 ws://127.0.0.1:8090
  Protocol/        sproto 源文件。改这里，并同步 Client/public/protocol/
  Doc/             参考资料、架构、进度
  Third/Atomic-Cannon/   对照用的开源实现，不链进 Client
```

`Server` 的 `skynet.exe`、`lualib`、`service`、`cservice`、`luaclib` 从 `F:\maplestory\server\project` 拷来。业务只在 `etc`、`dev`、`config`、`shell`。`dbApp` 连本机 MySQL 库 `fortress` 和 Redis。账号表上的 `cring` 是货币，`stock` 是库存，`loadout` 是 4 个出战格子。

## 进程

集群端口避开 MapleStory 的 5801–5804 / 8080。

| 进程 | 集群 | 入口 | 注册名 |
|---|---|---|---|
| gateApp | 127.0.0.1:6801 | `dev/gateApp` | `gate`，对外 websocket 8090 |
| loginApp | 127.0.0.1:6802 | `dev/loginApp` | `login` |
| worldApp | 127.0.0.1:6803 | `dev/worldApp` | `world`（房间列表）、`battle`（房间和对局） |
| dbApp | 127.0.0.1:6804 | `dev/dbApp` | `dbagent`（MySQL 账号、Redis 在线数） |

6801–6804 只在本机进程之间用。客户端只连 8090。MySQL 是 3306，Redis 是 6379，参数在 `etc/dbAppConf`。

`shell/start.bat` 拉起这四个进程，日志在 `Server/log`。`stop.bat all` 会结束本机全部 `skynet.exe`，包括别的工程。改了 Lua 或 `Protocol/` 之后要重启这四个进程。

网关按协议名转发：`rpcEcho` 本地回，`rpcAuthClient` 到 login，`csEnterLobby` / `csLeaveLobby` 到 `worldApp/world`，其余到 `worldApp/battle`。下推是 `cluster.send("gateApp", "gate", "push", fd, name, args)`。跨进程服务名要带 `@`，见 `dev/common/cluster.lua`。`websocket.accept` 留在监听回调的同步栈里，不能 `skynet.fork`。

断线同时通知 login、battle 和 world。login 把 Redis 里的在线计数减一。battle 在有人离开时把房间摘要标成消失，world 再推一份新的列表。

## 客户端

```
src/main.ts                 菜单、大厅、房间、操作条
src/game/BattleScene.ts     画天空、高度图、坦克、预瞄和飞行
src/game/controller.ts      本地 / 联机，排队播放 scResolve
src/sim/rules.ts            与服务端同一套结算，供本地双人和预瞄
src/sim/constants.ts        与 Server/config/constants.lua 同一组物理数
src/sim/tanks.ts            与 Server/config/tanks.lua 同一张坦克表
src/sim/items.ts            与 Server/config/items.lua 同一张道具表
src/net/codec.ts            sproto 编解码
src/net/socket.ts           二进制 WebSocket
```

画面 960×540，`Phaser.Scale.FIT` 塞进页面。碰撞不交给物理引擎：地形是 240 列高度（每列 4 像素），炮弹用定步长积分。

## 一局数据怎么走

进入游戏后先 `csEnterLobby`。world 立刻推 `scRoomList`，之后每次房间变化再推一整份列表，不是增量。建房、加入、选地图、选边、选坦克、准备、开始、回房间、离开都在 battle。battle 每次广播房间时，把摘要 `publish` 给 world。

本地人机测试不进这套房间。`csJoinBattle` 仍然是一个人打机器人，第二个人会换掉机器人。本地双人只在这一台浏览器里轮流操作。

联机对局：

1. `rpcAuthClient` 带名字和密码。库里没有这个名字就建号；已经有哈希就必须对上。通过后拿到固定 uid。
2. 房间里选的坦克写在成员的 `body` 上。开始时按这个 id 生成坦克。
3. `scState` 带地形、每辆坦克的种类、等待值、风力、谁的回合。
4. `csMove` 只改当前回合坦克的位置、燃料和等待值。
5. `csFire` 在 `rules.lua` 里检查射界和炮弹是不是这辆坦克的，再积分、挖地、结算伤害，推一条 `scResolve`。客户端先播轨迹，再换状态。这一回合用了双发就连续结算两发。`csUseItem` 扣库存并加 200 等待，不交回合。补给箱写在 `scState.crates` 里。
6. 第一轮按座位找下一个活人。每人都开过一炮之后，等待值最低的活人先动。相同等待值时座位小的先动。
7. 人机测试里，轮到机器人时约 1.5 秒后按和对手的距离走几步。1 号炮弹打得到就用 1 号，否则试 2 号，都打不到就随机。能量不够一次治疗量不喝药，打得到才用双发。

预瞄用客户端公式，落点以服务端为准。两端要一起改的表：`Client/src/sim/constants.ts` 对 `Server/config/constants.lua`，`Client/src/sim/tanks.ts` 对 `Server/config/tanks.lua`，`Client/src/sim/items.ts` 对 `Server/config/items.lua`。`weapons.lua` 里的四种炮弹只留给弹道对拍，对局不再发给玩家。

## 规则落在哪

| 事项 | 现在的做法 |
|---|---|
| 弹道 | 重力 500，水平风力 ±5，先加速度再位移。正风把炮弹推向画面右侧 |
| 坦克 | 12 种。能量、射界、燃料、等待和两发炮弹见参考资料 |
| 出手 | 第一轮按座位。之后等待值低的先动。普通弹 +100，特殊弹 +200，道具 +200，每步 +10。每回合 20 秒，每秒再 +10 |
| 道具 | 房间里用 CRING 买双发、小补、大补，最多带 4 格。地图上两个补给箱 |
| 地形 | 丘陵或峡谷。爆炸改高度列 |
| 坠落 | 脚底被挖开会掉下去，落差超过 40 像素另算坠落伤害 |
| 移动 | 燃料按坦克种类给。甲壳虫是 220。每步 22 像素、耗 10，等待 +10 |
| 房间 | 最多 8 人。红蓝人数相同且参战者都准备，房主才能开始。观战不计入 |

协议源文件只在仓库根的 `Protocol/`。`npm run dev` 和 `npm run build` 之前会把它们拷到 `Client/public/protocol/`。开发服务器另外直接读 `Protocol/`，避免拷贝过期。
